# astrbot_plugin_icloud_calendar

> 让你的 AstrBot 机器人用「自然语言」读写 **iCloud 日历**。
> 给机器人发一句“明天下午三点开会”，它就会自动帮你记进 iCloud；问它“这周有啥安排”，它会列给你看。

基于 CalDAV 协议直连 iCloud，支持 **添加 / 查询 / 修改 / 删除** 日程、**列出所有日历**，并提供 5 个
LLM 函数工具（`@filter.llm_tool`），大模型在对话中识别到日程或日历目录意图时会**自动调用**，
无需输入任何命令前缀。

---

## ✨ 功能

| 能力 | 自然语言示例 | 背后工具 |
|------|--------------|----------|
| 添加 | “帮我明天下午三点加个项目汇报，大概一个半小时” | `icloud_add_event` |
| 查询 | “这周有什么安排？” | `icloud_list_events` |
| 修改 | “把周五的会议推到下周一同一时间” | `icloud_update_event` |
| 删除 | “下周三体检取消掉” | `icloud_delete_event` |
| 列出日历 | “我有哪些日历？” | `icloud_list_calendars` |


> - **多日历**：查询 / 修改 / 删除默认覆盖账户下**全部日历**（可用 `query_all_calendars` 关闭）。
>   新增日程时：**说了写哪个日历**就写到指定日历（如“加到工作日历”，支持模糊匹配名称），
>   **没说**就写入默认的「写入日历」（`calendar_name`，留空＝第一个）。修改会在事件原所属日历内重建。
> - 修改采用「先新建后删除」的方式实现（规避部分服务端对 CalDAV 原地更新的兼容性问题）。
> - **日历目录**：询问“有哪些日历”时，agent 可调用 `icloud_list_calendars` 获取账户下最新的全部日历名称。

## 📦 安装

1. 把本目录放到 AstrBot 的插件目录：`AstrBot/data/plugins/astrbot_plugin_icloud_calendar/`
   （或在 WebUI 插件市场填入仓库地址安装）。
2. 安装依赖：插件加载时会用 AstrBot 当前运行的 Python 自动执行
   `pip install -r requirements.txt`（默认源失败时自动回退清华镜像），
   一般无需手动操作；依赖为 `caldav`、`icalendar`、`tzdata`。
   自动安装失败时可手动执行（日志中有具体原因）：
   ```bash
   pip install -r requirements.txt
   ```
3. 在 AstrBot WebUI 重载 / 启用插件。

> 需要 AstrBot 支持 `@filter.llm_tool` 的较新版本，并已在「服务提供商」中配置可用的
> LLM，且为会话开启了「函数工具 / function-calling」。

---

## 🔑 获取 iCloud「App 专用密码」（必须）

iCloud 不接受用 Apple ID 登录密码做 CalDAV 认证，必须使用 **App 专用密码**：

1. 浏览器打开 <https://appleid.apple.com> 并登录。
2. 进入 **登录与安全 → App 专用密码**（需已开启两步验证）。
3. 点「生成 App 专用密码」，命名如 `astrbot`，复制形如 `abcd-efgh-ijkl-mnop` 的密码。

## ⚙️ 配置

在 AstrBot WebUI 的插件配置页填写（对应 `_conf_schema.json`）：

| 配置项 | 说明 | 默认 |
|--------|------|------|
| `username` | Apple ID（iCloud 邮箱） | 空 |
| `password` | 上一步生成的 **App 专用密码** | 空 |
| `calendar_name` | **写入日历**名称（新增日程写到哪个日历）；留空＝账户下第一个日历 | 空 |
| `query_all_calendars` | 查询/修改/删除是否覆盖**全部日历**；关闭则只在写入日历内操作 | `true` |
| `timezone` | IANA 时区 | `Asia/Shanghai` |
| `caldav_url` | CalDAV 地址；大陆账户异常可试 `https://caldav.icloud.com.cn/` | `https://caldav.icloud.com/` |
| `default_duration_minutes` | 未给结束时间时的默认时长 | `60` |
| `list_default_days` | 查询默认天数 | `7` |
| `max_results` | 单次返回最大条数 | `20` |
| `inject_guidance` | 自动注入「当前时间 + 工具引导」 | `true` |
| `daily_reminder_enabled` | 是否启用每日定时提醒 | `false` |
| `daily_reminder_time` | 每日提醒时间（HH:MM，按上面的时区） | `08:00` |
| `daily_reminder_use_llm` | 播报内容由大模型按人格生成（失败回退固定模板） | `true` |
| `daily_reminder_session` | 提醒发送目标会话；建议用 `/日历 订阅` 自动填入 | 空 |

填好后，建议先发 `/日历 测试` 验证连接。
也可以直接发送 `/日历 日历列表`，列出账户下所有日历名称；该操作会强制刷新 CalDAV 日历目录。

日历目录会在每次查询、添加、修改、删除、`/日历 测试` 或 `/日历 日历列表` 操作开始时重新从 iCloud 获取；插件只在当前操作内复用该列表。新建或改名日历后，下一次操作会重新发现，不需要重载插件。

## 💬 使用

### 1）自然语言（推荐）

直接和机器人说话即可，例如：

- “帮我记一下，后天上午十点去医院复查”（写入默认日历）
- “把下周五下午三点的团建加到工作日历”（写入指定日历）
- “我这周有什么安排？”
- “把明天的例会改到下午四点”
- “周五的聚餐取消了”

机器人会自动调用相应工具完成操作并简洁回复。

### 2）指令（手动 / 自检）

| 指令 | 作用 |
|------|------|
| `/日历 帮助` | 查看帮助 |
| `/日历 测试` | 测试与 iCloud 的连接 |
| `/日历 日历列表` | 列出账户下所有日历 |
| `/日历 列表 [天数]` | 列出未来若干天的日程（默认 7 天） |
| `/日历 提醒` | 立即查看今天的日程 |
| `/日历 订阅` | 让机器人每天定时把当天日程发到**当前会话** |
| `/日历 退订` | 取消每日提醒 |

## ⏰ 每日定时提醒

让机器人每天固定时间主动把当天日程发给你，无需你开口。

**最简单的开启方式（推荐）：**

1. 在配置里设置 `daily_reminder_time`（如 `08:00`）。
2. 在**你希望收到提醒的那个聊天**里（私聊或群），发送一句 `/日历 订阅`。
   插件会自动把该会话记为发送目标并开启提醒。
3. 想取消就发 `/日历 退订`。

> `/日历 订阅` 本质是帮你自动填好配置项 `daily_reminder_session`（当前会话标识）
> 并把 `daily_reminder_enabled` 置为 `true`。你也可以在 WebUI 配置里手动填写这些项。

**说明：**

- 播报文案默认由**大模型按当前会话的人格（persona）风格生成**，而不是固定模板；
  未配置大模型、生成失败或关闭 `daily_reminder_use_llm` 时，自动回退到固定模板。
- 到点后插件会在 2 分钟容错窗口内推送一次，每天仅一次。
- 改了时间/目标/开关后即时生效，无需重载（后台每 30 秒检查一次）。
- 若当天没有日程，也会发一条提示（LLM 模式下同样由人格风格撰写）。
- 重启 AstrBot 后提醒仍有效（配置已持久化）；若重启时已过当天提醒时间，则当天不再补发。

## 🧠 关于 SKILL.md

[`SKILL.md`](./SKILL.md) 定义了“何时、如何”调用这些工具的引导规则。

- 当 `inject_guidance` 开启时，插件会在每次 LLM 请求前，自动注入
  **当前时间** + `SKILL.md` 正文（若文件缺失则使用内置精简引导），
  使大模型能正确换算“明天/下周三”等相对时间并主动调用工具。
- 你也可以把 `SKILL.md` 的内容粘贴进 AstrBot 的 **人格(Persona)** system prompt，
  然后把 `inject_guidance` 关掉，效果类似。

想调整触发策略或输出风格，直接编辑 `SKILL.md` 后重载插件即可。

## ❓ 常见问题

- **找不到日历**：插件会在每次日历操作开始时重新发现目录；如果刚刚在 iCloud 中新建或改名，下一次操作仍找不到，请确认 `calendar_name` 或工具参数中的名称，以及 `query_all_calendars` 是否关闭。
- **时间差了几个小时**：`timezone` 是插件统一的输入/显示时区，不是按日历分别配置的时区；检查它是否为你所在时区。带 `TZID` 或 `Z` 的外部日程会先按其来源时区解释，再转换到该配置时区显示。
- **返回的时间看起来多了一个时区偏移**：没有 `Z` 和 `TZID` 的 iCalendar 浮动时间按配置时区解释，不会再按 UTC 额外加一次偏移；若仍异常，检查外部日程是否带有错误的 `TZID`。
- **机器人不主动调用工具**：确认会话启用了 function-calling、`inject_guidance` 为开，
  或把 `SKILL.md` 配置为人格。
- **修改/删除了整组重复日程**：对“重复(周期)事件”当前按整组处理，建议对一次性事件使用；
  搜索时尽量带上 `search_date` 精确定位。

## 🛠 技术说明

- 时间统一转换为 **UTC** 存储（`DTSTART:...Z`）。添加时未带偏移的输入按配置的 `timezone` 解释；读取时，带时区的事件先按事件自身的 `TZID`/UTC 解释，无时区标记的浮动时间按配置时区解释，然后统一转回配置时区显示。
- 插件使用一个全局 `timezone` 作为输入和展示时区，不读取或覆盖 iCloud 各日历的独立显示偏好；因此同一绝对时间在不同配置时区下会显示为不同本地时间。
- 这样可避免 VTIMEZONE 兼容问题，并保证插件写入事件的绝对时间一致。
- `caldav` 为同步阻塞库，插件统一用 `asyncio.to_thread` 放入线程池执行，
  并以一把锁串行化，避免阻塞事件循环。
- 4 个工具均为协程并 `return str`：返回值会被 AstrBot 喂回给 LLM，
  由 LLM 按 `SKILL.md` 的格式组织最终回复。
